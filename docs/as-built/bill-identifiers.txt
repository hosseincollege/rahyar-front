Rahcom Bill Identifiers

Runtime source: the organization-scoped Rahcom database, stored per province in RahcomBillIdentifierList. The API is GET/PUT /rahcom/bill-identifiers and applies the same organization and assigned-province access checks as other Rahcom data.

The Isfahan reference/backup workbook is src/province-backup/ESF-electricity.xlsx. It is not read or rewritten during normal page use. The Electricity toolbar provides database backup download, restore from a backup workbook, upload of an external workbook, and download of the displayed table. Restore and upload replace the selected province's complete header/row snapshot after confirmation. Initial database setup requires restoring the workbook once after the backend schema is applied.

The frontend same-origin route at src/app/api/rahcom/bill-identifiers/route.ts preserves existing row add, edit, system assignment, and delete operations while persisting the snapshot through the authenticated Rahcom API. Backend schema, authorization, and persistence are defined in rahyar-back/prisma/schema/rahcom.prisma and rahyar-back/src/rahcom/rahcom.service.ts.

The electricity table toolbar includes a wrap-text toggle. When active, long non-code cell values can wrap to additional lines; when inactive, they stay on one line. The toggle leaves system codes and system assignments unchanged.

Schema update required before use: apply the new Prisma model in the Rahyar backend database, then restore src/province-backup/ESF-electricity.xlsx from the page toolbar. No migration or database push is run by the source edit.

Bill-to-system assignment is limited to one system family per bill: Rahcom, USO, or VSAT. A bill may be linked to multiple systems in that same family, including multiple Rahcom systems sharing one meter. The add and edit forms prevent mixing families, and the API validates assignments on row updates and workbook replacement. Existing mixed assignments can be cleaned in the edit form by removing the unwanted family. The add and edit forms include a complete code/name draft in the save request even when the plus button was not pressed.
