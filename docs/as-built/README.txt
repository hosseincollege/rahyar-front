مستند فنی As-Built پروژه رهیار
آخرین بازبینی: ۳۱ اکتبر ۲۰۲۶

هدف این پوشه
این مستند شرح وضعیت پیاده‌سازی‌شده پروژه است؛ یعنی اجزای واقعی، مسیر فایل‌ها، جریان داده و روش توسعه را ثبت می‌کند. با اضافه شدن قابلیت یا تغییر معماری، بخش مربوط باید هم‌زمان به‌روزرسانی شود. این مستند جایگزین کد یا تنظیمات استقرار نیست و نباید شامل رمز، کلید یا داده واقعی کاربران باشد.

۱) معرفی سامانه
رهیار یک سامانه وب سازمانی برای پایش و مدیریت عملیاتی سامانه‌های میدانی است. کاربران مجاز می‌توانند سامانه‌های استان خود را روی نقشه و در فهرست‌ها پیدا کنند، وضعیت و گزارش‌ها را بررسی کنند، خرابی و رخدادها را پیگیری کنند و فعالیت‌های تعمیراتی را ثبت کنند. داده‌ها با مرزبندی سازمان و استان مدیریت می‌شوند.

۲) معماری کلی
رابط کاربری: Next.js App Router و React با TypeScript در پوشه rahyar-front.
سرور برنامه: NestJS با TypeScript در پوشه sibling پروژه یعنی rahyar-back.
پایگاه داده: PostgreSQL؛ مدل‌ها با Prisma و schema چندفایلی نگهداری می‌شوند.
ارتباط: فرانت از APIهای احرازشده بک‌اند استفاده می‌کند. منطق مجوز و دسترسی مرجعاً در بک‌اند اعمال می‌شود.
رابط فارسی و راست‌چین است و زبان‌های دیگر از دیکشنری‌های مشترک رابط پشتیبانی می‌شوند.

۳) ساختار مهم فرانت‌اند
src/app/(workspace)/ : صفحات داخل محیط احرازشده.
src/app/(workspace)/rahcom/ : نقشه، سامانه‌ها، تردد، سولار، تیکت‌ها، اقدامات و صفحات وابسته.
src/app/(workspace)/settings/ : تنظیمات سازمان، کاربران، نقش‌ها، دسترسی‌ها و داده‌های رهکام.
src/components/layout/ : قاب برنامه، تاپ‌هدر، سایدبار و کنترل‌های مشترک.
src/components/preferences-provider.tsx : دسترسی رابط به ترجیحات مشترک کاربر/سازمان.
src/lib/api/rahcom/rahcom-api.ts : نوع‌ها و توابع ارتباطی API رهکام.
src/lib/rahcom-system-search.ts : منطق جست‌وجوی سامانه‌ها در تاپ‌هدر.
src/languages/ و src/lib/ui-messages.ts : زبان‌ها و متن‌های رابط؛ تغییر متن نمایشی باید در همه زبان‌های پشتیبانی‌شده منعکس شود.
src/provinces/ : داده‌های ثابت و قابل نگهداری محورها/استان‌ها، از جمله تعریف اصفهان.

۴) ساختار مهم بک‌اند
rahyar-back/src/core/ : زیرساخت مشترک مانند احراز هویت، گاردها و Prisma.
rahyar-back/src/rahcom/ : کنترلر، سرویس و DTOهای رهکام.
rahyar-back/src/settings/ : API و منطق تنظیمات.
rahyar-back/src/development/ : ابزارهای توسعه و داده نمایشی مجاز.
rahyar-back/prisma/schema/ : مدل‌های پایگاه داده به تفکیک دامنه.
rahyar-back/prisma/migrations/ : تغییرات نسخه‌بندی‌شده ساختار پایگاه داده.

۵) گردش درخواست
۱. کاربر در صفحه یا جزء رابط عملی انجام می‌دهد.
۲. صفحه از توابع دامنه‌ای src/lib/api استفاده می‌کند؛ فراخوانی مستقیم پایگاه داده از مرورگر وجود ندارد.
۳. درخواست به مسیر /rahcom یا /settings در بک‌اند می‌رود.
۴. گارد JWT هویت را بررسی می‌کند و RolesGuard مجوز نقش را اعمال می‌کند.
۵. Controller ورودی را به DTO می‌دهد؛ Service دامنه، محدوده سازمان/استان و قواعد دسترسی را بررسی می‌کند.
۶. Prisma داده را از PostgreSQL می‌خواند یا ذخیره می‌کند و پاسخ به رابط برمی‌گردد.

۶) امنیت و مرزبندی داده
مسیرهای محافظت‌شده رهکام با JwtAuthGuard و RolesGuard محدود شده‌اند. Serviceها باید دسترسی را سمت سرور کنترل کنند؛ مخفی کردن یک دکمه در رابط به‌تنهایی مجوز امنیتی محسوب نمی‌شود. داده‌های سامانه و گزارش باید با سازمان و استان انتخاب‌شده/مجاز محدود شوند. ورودی DTO اعتبارسنجی می‌شود. اطلاعات محرمانه در مستند، کد فرانت یا فایل نمونه قرار نمی‌گیرد.

۷) داده‌های رهکام
مدل‌های اصلی در prisma/schema/rahcom.prisma تعریف شده‌اند: RahcomSystem برای مشخصات سامانه، RahcomAxis برای محور، RahcomActivity برای فعالیت‌ها، RahcomSolarSnapshot و RahcomSolarSpecialSystem برای گزارش سولار و فهرست ویژه، RahcomTrafficSnapshot برای فایل/گزارش تردد، و RahcomImportedTicket برای تیکت واردشده. رابطه سازمانی در schema/organization.prisma نگهداری می‌شود. هر تغییر مدل باید migration متناظر داشته باشد.

۸) اجرای محلی و بررسی
فرانت: در rahyar-front دستور npm run dev (پورت پیش‌فرض 3015)، بررسی نوع‌ها با npx tsc --noEmit.
بک‌اند: در rahyar-back دستور npm run start:dev؛ ساخت با npm run build.
Prisma Client طبق تنظیمات پروژه از prisma/schema تولید می‌شود. پیش از اجرای migration مطمئن شوید نشانی پایگاه داده به محیط محلی درست اشاره می‌کند؛ migration روی محیط اشتباه می‌تواند داده را تغییر دهد.
کلیدها و متغیرهای محیطی را از فایل‌های نمونه/مستند محلی مورد اعتماد بگیرید و مقدار محرمانه را وارد Git نکنید.

۹) نگهداری مستند
هنگام افزودن صفحه، API، مدل، migration یا جریان داده، همین پوشه را به‌روز کنید. در تغییرات دامنه‌ای، فایل تخصصی ماژول را اصلاح کنید و تاریخ بازبینی را بنویسید. فقط رفتار موجود و قابل مشاهده در کد را به‌عنوان قابلیت قطعی ثبت کنید؛ موارد برنامه‌ریزی‌شده باید با برچسب «پیشنهادی/آتی» بیایند.

فایل‌های جزئیات
rahcom.txt : امکانات، صفحه‌ها و جریان داده ماژول رهکام.
settings-and-access.txt : تنظیمات، حساب‌ها، نقش‌ها و مرزبندی دسترسی.
فهرست روزانه راهداری: جریان بارگذاری و نمایش استان‌محور در road-list.txt ثبت شده است.
