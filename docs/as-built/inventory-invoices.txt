Rahcom Inventory and Invoices

The Inventory page reads and writes inventory records through the Rahcom API. It uses `RahcomDataListLayout` and `RahcomDataListToolbar` in `src/components/rahcom/data-list-layout.tsx` for the shared list frame, the Electricity toolbar icons/search capsule, loading/error/empty states, and table frame. The inventory table is rendered only when filtered database records are available. Download exports the filtered records to XLSX; unsupported upload/backup actions remain disabled.

The Invoices page uses `RahcomDataListLayout`, `RahcomDataListToolbar`, and the shared Rahcom table frame. Its authenticated `/rahcom/invoices` endpoint is organization- and selected-province-scoped. The first read creates an organization/province invoice workbook; for the `rahyar` organization and Isfahan only, that workbook starts with records transcribed from the visible messages in the Bale group «گروه مالی رهکام.اصفهان». Other organizations and provinces start empty. The table columns, in order, are شماره سند, تاریخ سند, شرح, کد سامانه/محور, مبلغ (ریال), ذی‌نفع, شماره شبا/حساب, وضعیت پرداخت, پیگیری‌های گروه, and تاریخ پیام. Search filters all columns, the wrap control exposes long notes, and download exports the displayed rows to XLSX. Per-invoice image attachments support invoice images, payment receipts, work-start photos, work-end photos, and other images. Files are stored outside the source folders under the project-level `Rahyar Storage/<PROVINCE-CODE>/<CATEGORY>/` tree; new uploads persist only a relative path and metadata in the database. Category directories include `Invoices`, `Payment Receipts`, `Work Start`, `Work End`, and `Other`. The root is configured with `RAHYAR_STORAGE_ROOT`; run `npm run storage:migrate-invoice-attachments` after applying the storage-path migration to move any legacy database blobs into files. Dates and identifiers retain the source message's spelling; absent details remain blank and are not inferred. Source implementation: `src/app/(workspace)/rahcom/invoices/page.tsx`, `src/lib/api/rahcom/rahcom-api.ts`; backend persistence and authorization: `src/rahcom/rahcom.controller.ts`, `src/rahcom/rahcom.service.ts`, `prisma/schema/rahcom.prisma`.

New Rahcom list pages must use `RahcomDataListLayout`; global toolbar, status, and table-frame adjustments belong in that shared component so all adopting pages stay aligned.
